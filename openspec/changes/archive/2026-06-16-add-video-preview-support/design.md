## Context

**当前状态**：
- 后端 VFS Service 已完整支持视频文件存储、FFmpeg 缩略图生成和 HTTP 服务
- 前端 MediaDetail 组件对视频仅显示占位符文本
- MediaGrid 组件对视频仅显示 🎬 图标，不显示缩略图
- MasonryItem 组件未区分图片/视频类型，尝试将视频缩略图作为图片加载

**约束条件**：
- 使用原生 HTML5 `<video>` 标签，无需引入第三方依赖
- 需要适配现有深色/浅色主题
- 保持与现有图片查看器一致的 UI 风格

## Goals / Non-Goals

**Goals:**
- 在 MediaDetail 中实现视频播放器，支持播放 MP4、WebM、MOV 格式
- 在 MediaGrid 中显示视频缩略图（而不是图标）
- 确保 MasonryItem 正确处理视频缩略图
- 添加视频播放器的样式，适配深色主题

**Non-Goals:**
- 不实现视频捕获功能（这是独立的 scope）
- 不添加高级视频编辑功能
- 不引入第三方视频播放器库

## Decisions

### 1. 使用原生 HTML5 `<video>` 标签
**选择**: 使用原生 `<video>` 而非第三方库（如 Video.js）

**理由**:
- 项目只需要基础的播放、暂停、进度控制，原生功能已足够
- 减少依赖体积和复杂度
- Chrome 原生视频播放器已提供良好的 UI 和功能

**替代方案考虑**:
- Video.js: 功能强大但过于重型，对于当前需求过度设计
- Plyr: 轻量但仍需要额外引入，原生已够用

### 2. 视频缩略图复用现有图片展示逻辑
**选择**: 视频缩略图使用与图片相同的 `<img>` 标签展示

**理由**:
- VFS Service 已为视频生成 JPEG 缩略图
- 复用现有组件逻辑，保持代码一致性
- 用户体验统一（缩略图外观一致）

### 3. 视频播放器配置
**选择**:
- 启用原生控件 (`controls`)
- 预加载元数据 (`preload="metadata"`)
- 不自动播放
- 内联播放（适用于移动端）

**理由**:
- 用户习惯原生播放器的交互方式
- 预加载元数据可以快速显示时长和第一帧
- 自动播放可能打扰用户

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 某些视频格式（如 MKV）Chrome 原生不支持 | 用户无法播放 | 在 UI 中显示友好提示，说明支持的格式 |
| 大视频文件加载慢 | 用户体验差 | 使用 HTTP 缓存，显示加载状态 |
| 视频缩略图生成失败 | 网格显示异常 | 降级显示视频图标，添加错误处理 |
